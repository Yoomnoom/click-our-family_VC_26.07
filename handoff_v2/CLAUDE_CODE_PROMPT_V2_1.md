## 0. 왜 V2.1인가 (먼저 이해할 것)

기존 V2 명세를 분석한 결과 재미를 죽이는 결함 3개가 발견됐다. 이번 작업은 이 3개를 고치는 것이 핵심이다.

1. **기다리는 게 항상 이득이다.** 명세대로면 구도 점수 최대 600점인데 사고 보너스는 80~350 단위로 합산되어 구도가 무너져도 기다릴수록 총점이 오른다. 플레이어는 늘 0초까지 기다리게 되고 "셔터 타이밍 고민"이 사라진다.
2. **조건 퍼즐이 다시 잡일이다.** 3개 조건(삼각 구도 등)을 모바일 세로 화면에서 드래그로 맞추게 하면, 발 마커를 이름만 바꾼 것과 같다. 심사위원은 1~3분만 플레이한다.
3. **플레이어는 사고를 구경만 한다.** 개입 수단이 셔터뿐이다.

공모전 심사위원이 첫 판에서 **"가족 때문에 사진이 기가 막히게 망했다"** 하고 웃는 것이 유일한 성공 기준이다. 기능을 늘리지 말고 이 한 가지에만 투자하라.

## 5. 게임 루프 상세

### 5-1. 상태 흐름

`briefing → staging → ready(0.6s 안내) → chaos(3.0s) → capture → result`

- `staging`: 드래그 자유. 셔터는 항상 눌 수 있다. 조건 충족 상태를 카드에 실시간 표시.
- 조건 2개가 **모두** 충족되고 **손가락을 뗀 뒤** 0.3초 유지되면 `ready` → 0.6초 안내("사진 망가지기 3초 전!") → `chaos`.
  - 드래그 중에는 절대 `ready`로 넘어가지 마라 (조작 중 갑자기 사고 시작 금지).
  - 조건 1개만 충족한 채 셔터를 누르면 즉시 촬영(사고 없음, 평범 등급 + "가족이 아직 준비 안 됐어요" 계열 자막). 이것도 정상 플레이다.
- `staging` 진입 후 15초가 지나도 `ready`가 안 되면 안내 토스트("가족이 지루해해요!") 후 **현재 상태 그대로 chaos 자동 시작**.
- `chaos`: 3.0초 카운트다운(3→2→1, 배경을 가리지 않는 큰 숫자, 셔터 링이 점점 붉어짐). 0초에 자동 촬영.
- `capture`: 셔터를 누른 **그 순간의 스냅샷**을 저장한다. 이후에 타이머·사고가 계속 진행되어 결과가 달라지면 안 된다. 셔터 직후 모든 사고 타이머와 애니메이션을 즉시 정지.

### 5-2. 레벨 데이터 (거실 3레벨)

조건 타입은 레벨 1·2·3에 필요한 것만 구현한다. 아래 임계값은 `03_GAME_RULES_SCORING.md`의 허용 범위를 기준으로 하되, **실제로 달성 가능한지 코드로 검증하고 조정**하라 (예: `applyDepth`의 스케일 범위가 좁아서 "12% 이상 크게"가 달성 불가능하면 임계값 또는 스케일 범위를 조정하고 기록).

| 레벨 | 제목 | 조건 2개 | 시작 시 미충족 | 사고 타임라인 (남은 초 기준) |
| --- | --- | --- | --- | --- |
| 1 | 첫 가족사진 | ① 얼굴 3개 보이기 ② 한 명은 크게 | ② | 2.2s 아빠 눈 감기 → 1.0s 동생 점프(위로 이탈) |
| 2 | 키 큰 사람은 뒤로 | ① 아빠는 뒤로(엄마보다 뒤) ② 둘은 꼭 붙기 | ① | 2.3s 누나 과한 브이 → 1.1s 엄마 급한 이동(옆으로 이탈) |
| 3 | 사고 직전 가족사진 | ① 삼각 구도 ② 한 명은 특수 자세(탭으로 변경) | ② | 2.0s·1.5s 연속 딴짓 2명 → 0.8s 고양이 중앙 난입 + 한 명 도망 |

- 레벨 1 제목은 명세의 "우리 집 삼각형"이 아니라 **"첫 가족사진"**으로 한다 (삼각 구도는 레벨 3으로 이동했으므로).
- 레벨 3의 "탭으로 자세 변경"은 이번에 새로 구현한다. **탭과 드래그 구분**: 이동 6px 미만 + 250ms 미만이면 탭. 탭 시 해당 인물의 `action` 포즈 ↔ 기본 포즈 토글, 선택된 인물에 이름 표시. 이 구분 때문에 기존 드래그 방어 코드가 깨지면 안 된다.
- 난이도 3종은 유지하되 **작은 매핑만** 한다: 편안하게(사고 시점이 약간 늦음, 동시 사고 없음), 보통(기본), 대환장(사고 간격 단축 + 추가 사고 1개). 난이도 때문에 로직이 복잡해지면 보통만 정상 동작하게 하고 나머지는 보고서에 "부분 구현"으로 적어라.

### 5-3. 사고가 구도를 실제로 무너뜨린다 (핵심)

사고는 이미지 교체 + **실제 DOM 좌표/크기 변경**이어야 한다. 예:

- 동생 점프: `bottom`이 약 +12% 올라갔다가 0.4초 뒤 복귀(점프 정점에서 찍히면 얼굴 위치가 바뀌어 구도 판정이 달라짐)
- 엄마 급한 이동: `left`가 약 ±14% 이동 후 유지 → "둘은 꼭 붙기" 같은 조건이 깨짐
- 고양이 난입: 화면 중앙으로 지나가며 근처 인물 1명을 밀어냄(해당 인물 좌표 변경)
- 눈 감기·브이·딴짓: 포즈 교체. 필요하면 소폭 이동

규칙:
- **늦은 사고일수록 구도를 더 크게 무너뜨리도록** 타임라인을 짠다 (마지막 사고가 가장 큰 사고이자 가장 큰 붕괴).
- 좌표 변경은 **스냅샷에 그대로 기록**되어 결과 사진에 재현된다.
- 사고는 레벨 데이터 테이블에 따라 **결정적으로** 발생한다. 무작위는 "누가 어느 쪽으로 이동하는지" 같은 미세 변동에만 쓰고, 어떤 사고가 언제 일어나는지는 고정이다.

### 5-4. 사고 중 드래그

- 사고를 치는 인물은 그 사고의 지속 시간(약 0.8초) 동안 잡을 수 없다 (`.dragging` 불가, 말 안 듣는 가족).
- 그 외 인물은 사고 타임 중에도 드래그 가능. 플레이어는 "사고 나는 사이 다른 가족으로 구도를 다시 맞추기"를 할 수 있다.
- 드래그 중인 인물에게는 사고를 걸지 않는다 (기존 `performChaos`의 `dragging` 가드 유지). 예약된 사고의 대상이 그 순간 드래그 중이면 **대상을 바꾸지 말고 그 사고를 0.4초 뒤로 한 번만 미룬다.** 미룬 뒤에도 드래그 중이면 그 인물의 드래그를 강제 해제하고 사고를 실행한다 (사고는 결정적으로 발생해야 한다).
- 이 규칙이 터치 안정성을 해치면(캐릭터 사라짐, 사고 중 끊김) **사고 중 드래그를 끄고** 보고서에 사유와 함께 기록하라. 이 경우 §6 점수는 그대로 유지한다.

## 6. 점수와 등급 (밸런스가 이 게임의 전부다)

### 6-1. 시작 공식 (조정 가능)

```
compRate   = 셔터 순간 충족한 조건 수 / 2        // 0, 0.5, 1
구도 점수   = round(100 × compRate)
사고 포인트 = 포착된 사고 포인트 합
              눈 감기 80 / 점프 100 / 과한 브이 100 / 엄마 급한 이동 120
              두 명 동시 딴짓 +250 / 고양이 중앙 난입 +300
배율 m      = compRate == 1   → 1.0
              compRate == 0.5 → 0.55
              compRate == 0   → 0.25
사고 점수   = 사고 포인트 × m
총점        = 구도 점수 × 4 + 사고 점수
```

핵심 의도: **사고를 많이 잡는 것보다, 구도가 살아있을 때 사고를 잡는 것이 더 높은 점수**다. 그래서 일찍 찍으면 안전하지만 밋밋하고, 끝까지 기다리면 사고는 크지만 구도가 무너져 배율이 깎인다. 최적은 중간 지점이다.

### 6-2. 밸런스 목표 (수락 기준)

"구도를 완벽히 맞춘 상태(compRate 1.0)로 chaos에 진입했다"고 가정하고 셔터 시점별 결과가 다음 방향을 만족해야 한다.

| 셔터 시점(남은 초) | 기대 등급 |
| --- | --- |
| 3.0 (사고 전) | 평범 |
| 약 2.0 (사고 1개 직후) | 제법 웃김 |
| 약 1.0 (사고 2개, 구도 대체로 유지) | 대참사 (레벨 3은 전설 가능) |
| 0 자동 촬영 | 구도 붕괴로 배율 하락 → **중간 시점 최고점보다 총점이 최소 15% 낮아야 함**. 등급은 제법 웃김~대참사 |

추가 조건:
- **전설의 가족사진**은 "compRate ≥ 0.5 + 2사건 이상 포착"에서만 나온다. 구도가 완전히 0이면 전설 불가.
- 어느 레벨에서도 "항상 0초까지 기다리는 전략"과 "항상 즉시 찍는 전략"이 최적이 되면 안 된다.
- 등급 임계값(평범/제법 웃김/대참사/전설)은 레벨별 최대 가능 점수를 고려해 **레벨별 테이블로 조정해도 된다**.

### 6-3. 밸런스 시뮬레이션 (필수)

점수·등급·조건 판정 로직은 DOM에 의존하지 않는 **순수 함수**로 분리하고, Node에서 돌릴 수 있는 시뮬레이션 스크립트를 만들어라(`tools/balance_sim.js` 등, 빌드 도구 추가 금지).

- 레벨 1·2·3 × 셔터 시점 {3.0, 2.5, 2.0, 1.5, 1.0, 0.5, 0} × (구도 완벽 / 구도 절반) 조합의 총점·등급 표를 출력
- 위 §6-2 기준을 만족하는지 PASS/FAIL로 표시
- FAIL이면 수치를 조정하고 재실행. 최종 표를 보고서에 포함

## 7. UX·연출 (웃음의 대부분은 여기서 나온다)

`04_UX_SCREEN_SPEC.md`를 따르되 아래를 **반드시** 포함한다. 새 이미지는 만들지 마라. CSS 애니메이션과 텍스트로 해결한다.

### 7-1. 플레이 중
- 조건 카드: 상단 2개. 충족 시 체크 + 짧은 바운스. 문장 14자 이내, `word-break: keep-all`.
- 사고 타임: 큰 3·2·1, 셔터 링 점점 붉어짐, **말풍선 최대 1개**("아빠 눈 감는다!"), 두 사고가 겹치면 "지금이야!" 토스트.
- 토스트 22자 이내, 동사형 ("아빠를 뒤로!").

### 7-2. 셔터 → 결과 (가장 중요한 연출)
1. 셔터 순간 **0.15초 정지(프리즈 프레임)** + 플래시
2. 사진이 **인화되듯 나타남** (약 0.8초, 흐림→선명 또는 위에서 내려오는 인화 효과)
3. 등급 **스탬프가 쾅 찍히는** 애니메이션 (전설·대참사는 더 크게, 흔들림 포함)
4. 사진 위에 **손글씨풍 자막**(사건 요약 제목): "아빠는 꿈속, 동생은 공중"
5. 점수 3항목(구도·순간·사고)이 **차례로 카운트업**
6. 가장 큰 버튼은 "다음 사진", 그 아래 보조로 "한 번 더 찍기", "가족 앨범"

사진은 화면의 55% 이상. 등급이 점수보다 먼저 보인다.

### 7-3. 제목·문구
- 포착된 사건 조합에서 제목을 생성한다. 조합별 문구 테이블을 **최소 10개** 만들어라 (예: 눈 감기만 / 점프만 / 눈 감기+점프 / 브이+엄마 이동 / 두 명 딴짓 / 고양이 난입 / 전부 / 사고 전에 찍음 / 구도 붕괴 / 조건 미충족 촬영).
- `07_ASSET_AND_COPY_GUIDE.md`의 예시 문구를 활용하되 반복 느낌이 나지 않게 같은 조합에도 2~3개 변형을 둔다.
- 일찍 찍은 경우 "완벽했는데 아무 일도 안 일어났다" 계열이 아니라 **다음에 기다려보고 싶게 만드는** 문구를 쓴다 (예: "너무 평화로운데요? 가족이 뭔가 숨기는 눈치").

### 7-4. 효과음·진동 (P1, 시간이 남을 때만)
- WebAudio로 짧은 합성음(카운트다운 틱, 셔터, 스탬프)과 `navigator.vibrate`(미지원 시 무시). 외부 오디오 파일 금지. 음소거 토글 필수. 구현 못 하면 "미구현"으로 보고.

### 7-5. 잠금
- 레벨 3 결과 후 "다음 사진"을 누르면 **"거실 앨범 완성!"** 화면 → 앨범으로 이동. 문구: "다음 앨범 준비 중 (생일·소풍)". 레벨 4 이상으로 절대 진행하지 않는다.
- 타이틀 화면에서도 생일·소풍은 비활성 표시.

## 9. 검증 (직접 실행하고, 실행하지 못한 것은 정직하게 "미검증"으로)

### 9-1. 자동 검증
- 순수 함수 단위 테스트: 조건 판정(각 타입 경계값), 점수 계산, 등급 판정, 제목 생성
- 밸런스 시뮬레이션 (§6-3)
- 가능하면 Playwright(없으면 설치 시도, 불가하면 대체 수단 명시)로 헤드리스 브라우저에서:
  - 뷰포트 360×640, 390×844, 412×915, 768×1024에서 타이틀→레벨 1→결과→레벨 2→레벨 3→앨범 완주
  - 위·아래·대각선 빠른 드래그 각 20회 중 캐릭터 소실 0건 (`pointercancel` 포함)
  - 콘솔 오류 0, 이미지 404 0
  - 셔터 순간 스냅샷의 좌표·크기·z-index가 결과 사진 DOM과 일치 (허용 오차 0.5%)
  - 새로고침 후 진행 레벨·최고점·앨범 유지
  - `staging` 15초 자동 시작, 0초 자동 촬영, 조건 1개 즉시 촬영 모두 정상
  - 사고 중 드래그 가능/불가 규칙, 드래그 중 `ready` 진입 차단
- 스크린샷을 찍어 직접 눈으로 확인: 글자 한 글자 낙하, 버튼 잘림, 캐릭터 전신 잘림

### 9-2. 사람이 해야 하는 검증 (이 목록은 보고서 맨 아래에 그대로 붙여라)
사용자가 일어나서 **설명 없이** 플레이한 뒤 확인할 질문:
1. 무엇을 하는 게임이라고 이해했나?
2. 언제 셔터를 누를지 고민했나?
3. 결과 사진에서 무엇이 웃겼나?
4. 한 판 더 하고 싶나?

4개 중 3개가 긍정이면 확장, 2개 이하면 콘텐츠 추가 금지·핵심 루프 재검토. **이 판정은 Claude가 하지 않는다.**

## 11. 우선순위가 충돌할 때의 판단 기준

1. 모바일에서 캐릭터가 사라지거나 터치가 먹통이 되지 않는 것
2. 결과 사진이 플레이어가 만든 구도를 그대로 재현하는 것
3. "일찍 찍기 vs 기다리기"가 실제로 고민되는 것 (§6)
4. 결과 화면의 웃음 연출 (§7-2)
5. 나머지 (난이도 세분화, 효과음, 앨범 확대 보기 등)

시간이 부족하면 5번부터 포기하고 보고서에 "미구현"으로 적어라.
