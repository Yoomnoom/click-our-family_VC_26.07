# 「찰칵! 우리 가족」 V2.1 거실 3레벨 — 완료 보고서

## 구현 완료

- 상태 흐름 `briefing → staging → ready(0.6s) → chaos(3.0s) → capture → result`, 드래그 중 ready 진입 차단(손 뗀 뒤 0.3초 유지), staging 15초 자동 시작, 0초 자동 촬영, 조건 1개 즉시 촬영.
- 레벨당 조건 정확히 2개, 시작 시 미충족 1개(레벨별 시작 배치 후보 + 실행 시 검증·대체).
- 사고가 실제 좌표/크기를 바꿔 구도를 무너뜨림(결정적 사고 + 방향 선택 `planMoves`), 스냅샷에 그대로 기록.
- 사고 중 드래그(사고 치는 인물은 0.8초 잠금, 드래그 중인 대상은 0.4초 미룬 뒤 강제 해제).
- 탭/드래그 구분(6px·250ms), 레벨 3 특수 자세 탭.
- 점수 = 구도×4 + 사고(배율 반영), 등급 4종, 제목 13개 조합 키·변형 포함 고유 문구 28개.
- 결과 연출: 0.15초 프리즈 + 플래시 → 인화(0.9s) → 손글씨 자막 → 등급 스탬프(대참사·전설은 크게+흔들림) → 구도·순간·사고 카운트업 → "다음 사진"이 가장 큰 버튼.
- 효과음(WebAudio 합성)·진동·음소거 토글(P1).
- 저장: `familyPhotoV2Level`, `familyPhotoV2Best`, 앨범 V2 필드(`version:2, rarity, scoreParts, events, title`), 구버전 기록 호환.
- 순수 로직 분리 + `tools/balance_sim.js`, `tools/logic_tests.js`, `tools/e2e_check.js`.

## 부분 구현
- **난이도 3종**: 편안하게(사고 0.3초 늦게, L3 동시 딴짓 제거) / 보통 / 대환장(사고 간격 25% 단축 + 추가 사고 1개)을 `buildEvents`로 매핑. 밸런스 시뮬레이션 기준은 **보통만** 검증. 편안/대환장은 구동만 확인(시뮬레이션 표에 포함, 기준 판정 없음). V1의 난이도별 점수 배율은 폐기.
- **전설 등급**: L1·L2는 사고가 2개뿐이고 §6-2 표(1.0초=대참사)와 충돌해 전설 기준을 도달 불가로 설정. 전설은 L3에서만, 구도가 무너지기 직전 약 0.35초 창(남은 약 0.3~0.65초)에 찍어야 나옴.
- **구도 붕괴의 임의 배치 강건성**: 조건 2개 충족 무작위 배치 2000개당 "0초 자동촬영이 중간 최고점보다 15% 이상 낮음" 비율 — L1 약 98%, L2·L3 100%. 일부 L1 배치는 붕괴가 부족(그 경우 기다리는 편이 유리).
- 셔터 직후 "모든 애니메이션 즉시 정지": 사고 타이머·이벤트는 즉시 폐기하지만, 이미 진행 중이던 CSS 이동은 0.15초 프리즈 동안 끝까지 진행(플래시에 가려짐). 결과 사진은 셔터 순간 `getBoundingClientRect` 스냅샷이라 영향 없음.

## 알려진 문제
- 구도가 앞뒤로 크게 흩어진 일부 L1 배치는 한 번의 사고로 "한 명은 크게"가 깨지지 않아 기다리기가 유리할 수 있음(약 2%).
- 조건 판정은 이미지 박스 기반 근사(얼굴 위치 = 박스 상단 16%). 포즈 이미지마다 실제 얼굴 위치는 조금 다름.
- 레벨 3 첫 시작 위치·조건 임계값은 세로 화면 4종 기준으로 검증. 가로 데스크톱 레이아웃은 가족 크기가 달라 조건 시작 상태를 실행 시 자동 보정하지만 e2e 미검증(스크린샷 1920×1080 미확인).
- 실제 사람 손가락·실기기 터치 테스트는 하지 못함(에뮬레이션만).
- 오디오·진동은 소리/진동 출력 자체는 미검증(코드 오류 없음만 확인).
- 이 문서의 e2e 통과 수치는 최종 실행 로그 기준.

## 결정 기록 (사용자에게 물을 수 없어 내린 판단)
1. **이미지 자세**: 파일을 열어 확인한 결과 명세의 사고 이름과 그림이 일치해 이름 변경 없음. 아빠 눈 감기=action(꾸벅), 엄마 이동=action(달리기), 누나 브이=action2·폰=action, 동생 점프=action·메롱=action2. 아빠 action2(재채기)·엄마 action2(머리 헝클기)는 "추가 사고"(대환장 난이도)로 사용.
2. **깊이 배율 변경**: `max(.82, 1-y*.004)` → `max(.68, 1-y*.007)`. 기존은 최대 18% 차이라 "한 명은 크게(12%↑)"가 사실상 달성 불가였음. 임계값 1.12는 유지, 경계 y가 드래그 가능 범위 안임을 단위 테스트로 확인.
3. **조건을 특정 인물에 묶음**: L2는 "엄마 아빠 꼭 붙기"(임의 둘이 아니라 엄마·아빠), 사고 인물이 조건 인물이라 붕괴가 안정적으로 발생. "한 명은 크게"는 *깊이 배율(앞쪽에 섬)* 기준(절대 키가 아니라 플레이어가 만드는 크기), 카드 문구는 "한 명은 크게 앞으로".
4. **등급은 사고 점수(배율 반영) 기준**: 총점 기준이면 0초 자동촬영이 "웃김~대참사" 요건과 "평범 3.0초 = 총점 400"이 충돌해 불가능했음. 사고 점수 기준 임계값(웃김 60 / 대참사 150 / 전설 L3 500).
5. **"순간/사고" 분리**: V2.1 공식엔 순간 점수가 없어, 개별 사고 포인트=순간, 두 명 동시 딴짓·고양이 난입 보너스=사고로 표시(합계는 공식과 동일).
6. **사고 중 드래그 유지**: 터치 안정성 문제 없음(스트레스 테스트 통과)이라 폐기하지 않음.
7. **점프는 0.3초 간격으로 계속 튀는 동작**(포즈 유지): 한 번만 뛰고 착지하면 0초 자동촬영에서 점프가 안 잡혀 등급이 평범으로 떨어지는 문제가 있었음.
8. **고양이**: 사진 중앙에 도착해 계속 앉아 있음(자동촬영에도 포착). 도착 0.15초 뒤부터 포착.
9. **사고 시점 해석**: 이동은 사고 시작 후 0.5초에 완료되는 것으로 보고 시뮬레이션과 판정을 맞춤(`SETTLE`). 실제 화면은 이동 중 상태를 그대로 찍음.
10. **다시 찍기**는 브리핑을 건너뛰고 바로 staging, **앨범 열기**는 진행 중 라운드를 중단 후 같은 레벨 브리핑으로 복귀.
11. **테스트 훅** `window.__game`(읽기 전용)을 노출 — e2e 용도. 배포 시 제거해도 게임은 동작.
12. 폰트는 기존대로 Google Fonts `@import`(오프라인 시 대체 폰트).
13. 난이도 키(`familyPhotoDifficulty`)와 앨범 키(`familyPhotoGallery`)는 기존 것을 공유(지시문이 앨범은 읽으라고 함).
