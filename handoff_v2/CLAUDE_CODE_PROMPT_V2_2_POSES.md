## 1. 이번 변경의 핵심 한 줄

**가족 한 명당 6포즈를 "기본 1 + 연출 2 + 사고 3"으로 나눠, 연출은 플레이어가 탭으로 고르고 사고는 가족이 알아서 친다. 사고 포즈 중 일부는 얼굴을 가려서 구도 조건을 실제로 깬다.**

이렇게 하면 V2.1에서 부족했던 두 가지가 해결된다.
- 플레이어의 탭 조작에 의미가 생긴다 (연출 포즈 → 점수·레벨 3 조건).
- 사고가 점수 숫자만 올리는 게 아니라 구도 조건(얼굴 보임)을 실제로 무너뜨린다 → "일찍 찍기 vs 기다리기" 고민이 강화된다.

## 2. 포즈 역할 배정 (그림 확인 후 확정)

숫자는 업로드된 파일 번호(`{id}-p{n}.png`)다. 설명은 그림을 보고 내가 해석한 것이므로 §0-4에서 검증하라.

| 인물 | base (기본) | wave (연출) | special (연출) | chaos 1단계(작음) | chaos 2단계(중간) | chaos 3단계(큼) |
| --- | --- | --- | --- | --- | --- | --- |
| 엄마 `mom` | p1 손 모으고 웃음 | p2 손 흔들기 | p6 손가락으로 가리킴 | p3 옷 정리(고개 숙임) **얼굴 가림** | p4 급하게 달려가며 손 뻗음 **이동** | p5 머리 감싸 깜짝 **고양이 반응** |
| 아빠 `dad` | p6 양손 주머니 | p5 손 흔들기 | p3 엄지 척 | p4 눈 감고 웃음 **눈 감기** | p1 얼굴 가리고 숙임(재채기) **얼굴 가림** | p2 깜짝 놀라 양손 듦 **고양이 반응** |
| 누나 `sis` | p4 손 뒤로 | p5 손 흔들기 | p6 윙크+브이 | p1 폰 보는 옆모습 **얼굴 가림** | p2 깜짝 놀람 **고양이 반응** | p3 공중 점프 **공중** |
| 동생 `bro` | p6 양손 주머니 | p5 손 흔들기 | p3 메롱 | p2 엎드려 바닥 짚음 | p4 공중 점프 **공중** | p1 달리는 자세 **이동·고양이 반응** |

- 이 배정은 `pose_meta_draft.json`에 이미 들어 있다. 이를 정식 `POSE_META`로 승격해 `index.html`에 **인라인**한다 (런타임 fetch 금지).
- 명세의 "누나 과한 브이"는 **사고에서 제외**하고 연출 포즈(윙크+브이)로 옮겼다. 사고 이름은 위 표의 포즈 의미를 따른다.
- `faceAnchor`는 비어 있다. **각 포즈의 얼굴 중심 좌표(캔버스 대비 %)를 직접 측정해 채워라.** 팔이 위로 올라간 포즈(누나 p3, 동생 p4)나 몸을 숙인 포즈(엄마 p3, 아빠 p1)는 bbox 상단으로 추정하면 틀리니 이미지를 보고 판단하라. 측정 후 **얼굴 앵커를 이미지 위에 점으로 찍은 확인 이미지를 24장(또는 시트 4장)으로 생성**해 눈으로 검증하고, 틀린 것을 고쳐라. 이 검증 이미지는 `handoff_v2/pose_verify/`에 남긴다.

## 3. 렌더링·CSS 개편 (가장 위험한 부분)

기존 이미지는 여백 없이 꽉 잘려 있었고, 포즈마다 `.char-img{width:122%;margin-left:-11%}` 같은 **포즈별 크기 보정 CSS**가 붙어 있다. 새 이미지는 전부 같은 509×556 캔버스에 투명 여백이 있다. 따라서:

1. **포즈별 보정 CSS(`.char-img` width/margin 변형, `.pose-v1/.pose-v2`, `.sleep-mode/.phone-mode/.jump-mode/.fix-mode` 전용 규칙)를 새 포즈 경로에서는 전부 제거**하고 단일 규칙으로 통일한다. 구버전 앨범 기록 렌더링에 필요한 규칙만 `.legacy` 계열로 격리해 남긴다.
2. 캐릭터 컨테이너는 `aspect-ratio: 509 / 556`로 고정하고 이미지는 `object-fit: contain; object-position: center bottom`.
3. **인물별 표시 크기는 기본 포즈의 눈에 보이는 높이 비율로 맞춘다.** 측정값(캔버스 556px 중): 아빠 502 · 엄마 486 · 누나 447 · 동생 395 → 아빠 1.00 : 엄마 0.97 : 누나 0.89 : 동생 0.79. 기존 비율(아빠 58 : 엄마 54 : 누나 48 : 동생 43)과 비슷하므로 시각적 위화감이 없게 컨테이너 높이를 이 비율로 재산정한다.
4. **드래그 경계와 "화면 안" 판정은 캔버스 전체가 아니라 눈에 보이는 영역(bbox) 기준**으로 계산한다. 그렇지 않으면 캐릭터가 화면 끝까지 못 가거나, 여백 때문에 "화면 안" 판정이 틀린다. 포즈가 바뀌면 bbox도 바뀌므로 포즈별 bbox를 사용한다. 기존 `moveDrag`의 `half/maxY` 계산을 이 기준으로 교체하되 **모바일 터치 방어(`touch-action:none`, `pointercancel` 등)는 그대로 유지**한다.
5. 점프 포즈(누나 p3, 동생 p4)는 이미지 자체가 캔버스 안에서 떠 있다(바닥 여백이 큼). **이미지가 이미 떠 있으므로 점프 때 추가 이동은 작게(최대 +4%)** 하거나 하지 마라. 이중으로 띄우면 화면 밖으로 나간다.
6. 그림자: 현재 `drop-shadow`가 이미지에 붙어 있어 점프 포즈에서 그림자도 같이 뜬다. **컨테이너 바닥에 고정된 타원 그림자 요소**를 따로 두면 점프가 훨씬 자연스럽다 (P1, 시간 남으면).
7. **포즈 프리로드 필수**: 시작 시 24장 전부 `new Image()` + `decode()`로 미리 로드한다. 사고 중 포즈 교체에서 빈 프레임이 보이면 웃긴 순간이 망가진다.
8. 포즈 교체에는 0.12초짜리 짧은 팝(scale 1→1.06→1)을 줘서 사고가 눈에 띄게 한다. 위치·크기 계산에는 영향을 주지 않는다 (스냅샷은 팝 애니메이션이 아닌 최종 값 기준).

## 4. 데이터 모델

```js
// 인물 상태: 파일 경로가 아니라 포즈 ID를 단일 출처로 삼는다
member = { id:'dad', x, y, poseId:'dad-p6', poseRole:'base' }

POSE_META['dad-p4'] = {
  char:'dad', n:4, file:'assets/poses/dad-p4.png',
  role:'chaos', severity:1, key:'eyes_closed', points:80,
  faceVisible:true, eyesClosed:true, airborne:false, moves:null, reaction:null,
  bbox:{x0,y0,x1,y1}, faceAnchor:{x,y}   // 캔버스 대비 % 또는 px, 하나로 통일
}
```

- `captureMembers()`가 기록하는 스냅샷에 **`poseId`를 반드시 포함**한다. 결과 사진·앨범은 `poseId`로 이미지를 재구성한다.
- 구버전 기록(`pose` 경로 문자열 + `state`)은 기존 방식으로 계속 렌더링한다. 신버전 기록은 `version:2`, `poseId`를 쓴다.
- 기존 `performChaos()`의 `variant`, `actionPortraits`, `actionPortraits2`, 상태 클래스 기반 로직은 신규 경로에서 **제거**하고 `setPose(memberId, poseId)` 하나로 통일한다.

## 5. 규칙 개정

### 5-1. 탭으로 연출 포즈 순환 (신규, 레벨 1~3 공통)
- 인물을 탭(이동 6px 미만 + 250ms 미만)하면 `base → wave → special → base` 순으로 순환한다. 사고 중인 인물은 탭 무시.
- 탭한 인물에게 포즈 이름 라벨을 0.8초 표시한다 ("손 흔들기", "엄지 척" 등 2~4글자).
- 탭/드래그 구분 때문에 기존 드래그가 깨지면 안 된다. 20회 빠른 드래그 테스트(V2.1 §9)를 이 변경 후에 다시 수행한다.

### 5-2. 얼굴 보임 판정이 포즈를 반영한다 (신규)
- `faceVisible:false` 포즈(엄마 p3, 아빠 p1, 누나 p1)에 있는 인물은 **얼굴 개수에서 제외**한다. 사고가 실제로 조건을 깬다.
- 레벨 1 조건 "얼굴 3개 보이기"가 이 규칙의 혜택을 가장 크게 받는다. 사고 대상 선정 시 **사고 포즈가 조건을 깨는지**를 의식해 타임라인을 짠다 (§6).

### 5-3. 레벨 3 "한 명은 특수 자세" 정의
- `poseRole === 'special'`인 인물이 1명 이상이면 충족. wave는 불충족 (특수 자세는 두 번 탭해야 나오는 연출이어야 성취감이 있다).

### 5-4. 연출 포즈 점수 반영
- 구도 점수 = `round(80 × compRate) + min(20, 7 × 연출포즈 인원)`
  - 연출포즈 인원 = 셔터 순간 `wave`/`special` 포즈이면서 `faceVisible:true`인 인물 수
- 총점 공식의 나머지 구조(구도×4 + 사고점수, 사고점수 = 포인트 × 구도 유지 배율)는 V2.1 §6을 유지한다.
- 연출 포즈를 쓸 이유가 레벨 1·2에서도 생기도록 한다: 이 규칙만으로도 연출 포즈 3명이 구도 점수 +20.

### 5-5. 사고 단계 에스컬레이션
- 한 인물이 한 판에서 여러 번 사고를 치면 **다음 단계의 포즈**로 올라간다 (1단계 → 2단계 → 3단계). 같은 그림이 반복되면 웃음이 식는다.
- 레벨 타임라인은 아래 §6처럼 **인물·단계를 명시**한다. 데이터 기반으로 결정적으로 발생한다 (V2.1 §5-3 원칙 유지).

### 5-6. 고양이 연쇄 반응 (신규, 이번 개편에서 가장 웃길 부분)
- 고양이가 중앙에 난입하는 순간, `reaction:'cat'` 포즈를 가진 인물 중 **고양이와 가장 가까운 최대 2명**이 자기 반응 포즈로 즉시 전환한다 (엄마 p5, 아빠 p2, 누나 p2, 동생 p1).
- 동생은 `p1`(달리기)로 바뀌면서 **고양이 쪽으로 8~10% 이동**한다 (쫓아가기).
- 반응 사고는 포즈 자체 점수만 받고 별도 가산은 없다. 고양이 중앙 난입 +300은 V2.1 그대로.
- 반응 대상은 선택 로직이 결정적이어야 한다 (거리 기준 정렬, 동률은 인물 ID 순).

## 6. 레벨별 사고 타임라인 (시작안, 밸런스 시뮬레이션으로 조정)

| 레벨 | 조건 2개 | 타임라인 (남은 초) |
| --- | --- | --- |
| 1 첫 가족사진 | 얼굴 3개 보이기 · 한 명은 크게 | 2.2s 아빠 `p4` 눈 감기 → 1.0s 동생 `p4` 점프 |
| 2 키 큰 사람은 뒤로 | 아빠는 뒤로 · 둘은 꼭 붙기 | 2.3s 누나 `p1` 폰 보기 → 1.1s 엄마 `p4` 급한 이동(옆으로 약 14% 이탈) |
| 3 사고 직전 가족사진 | 삼각 구도 · 한 명은 특수 자세 | 2.0s 아빠 `p1` 재채기 → 1.5s 엄마 `p3` 옷 정리 → 0.8s 고양이 난입 + 연쇄 반응(§5-6) |

- 레벨 1에서 아빠 `p4`(눈 감기)는 얼굴이 보이므로 얼굴 개수는 유지되고 "사고 포착"만 일어난다. 후반 동생 점프로 구도(한 명 크게 등)가 흔들린다.
- 레벨 3은 재채기·옷 정리로 **얼굴 2개가 연달아 사라져** 삼각 구도 조건이 확실히 무너진다. 이게 "두 명 연속 딴짓"의 실제 효과다.
- 난이도 매핑(편안하게/보통/대환장)은 V2.1 §5-2 그대로.

## 7. 검증

### 7-1. 신규 자동 검증
- 24장 전부 로드 성공, 404 0, 프리로드 후 포즈 교체 시 빈 프레임 없음
- `POSE_META` 무결성: 인물당 base 1 / wave 1 / special 1 / chaos 3, 파일 존재, bbox가 캔버스 내부, faceAnchor가 bbox 내부
- 포즈 순환: 탭 3회 후 원래 포즈로 복귀, 사고 중 탭 무시
- 얼굴 개수: `faceVisible:false` 포즈 인물이 제외되는지 경계 테스트
- 드래그 경계: 포즈 교체(예: 엄마 p4처럼 가로로 넓은 포즈) 후에도 눈에 보이는 영역이 stage 밖으로 나가지 않음, 캐릭터 소실 0건 (4개 뷰포트 × 위·아래·대각선 빠른 드래그 20회)
- 스냅샷 일치: 셔터 순간 스냅샷의 `poseId`·좌표·크기·z-index가 결과 사진 DOM과 허용 오차 0.5% 이내 일치. 앨범 재렌더링 후에도 동일
- 구버전 앨범 기록 로드 시 오류 없음 (구버전 샘플 기록을 만들어 테스트)
- 밸런스 시뮬레이션 재실행: V2.1 §6-2 기준 PASS/FAIL 표를 새 점수 체계로 다시 출력하고, FAIL이면 수치를 조정해 PASS로 만든다. 연출 포즈 보너스(§5-4)와 연쇄 반응(§5-6) 포함

### 7-2. 시각 확인 (스크린샷을 찍어 직접 본다)
- 360×640, 390×844에서 4명이 같은 화면에 섰을 때 인물 크기 비율이 자연스러운지
- 점프 포즈에서 그림자·위치가 어색하지 않은지
- 얼굴 앵커 확인 이미지(§2)
- 레벨 3의 고양이 난입 순간 프레임 (연쇄 반응이 화면에서 읽히는지)

### 7-3. 사람이 해야 하는 검증
V2.1 §9-2의 4개 질문 그대로. 이번 개편으로 추가로 사용자가 직접 봐야 할 것:
- 포즈 6종이 인물 성격과 맞게 느껴지는지 (역할 배정이 마음에 드는지)
- 탭으로 포즈를 바꾸는 게 재미있는지, 귀찮은지

V2.1 §10 항목에 아래를 추가한다.

- 결정 기록: 역할 배정 수정 여부, 인물 크기 비율 재산정 값, 점프 이중 이동 처리, 연쇄 반응 대상 선택 규칙, 연출 보너스 수치 조정
- 새 ZIP 파일명에 `v2_2_poses` 표기. 기존 ZIP 덮어쓰기 금지

## 9. 충돌 시 우선순위

1. 모바일 드래그·터치 안정성 (캐릭터 소실 0)
2. 결과 사진이 플레이어가 만든 구도와 포즈를 그대로 재현
3. 포즈 교체가 매끄럽고 인물 크기·위치가 자연스러움 (프리로드, bbox 기준 경계)
4. "일찍 찍기 vs 기다리기" 고민이 유지됨 (밸런스 시뮬레이션 PASS)
5. 고양이 연쇄 반응, 그림자, 효과음 등 연출

시간이 부족하면 5번부터 포기하고 "미구현"으로 보고한다. 실행하지 않은 검증을 통과했다고 쓰지 마라.
